# План: мобильная версия

Рабочий документ для адаптации интерфейса под телефон и планшет. Делаем **после** правок механик.
Принцип тот же, что в [BACKLOG.md](BACKLOG.md): задача → своя ветка от `dev`, слияние `--no-ff`,
проверка в браузере на всех сеттингах.

## 0. Принцип

- **Не переписываем, а даём течь.** Десктоп остаётся как есть — это эталон. Мобильная версия это та
  же вёрстка, которой на узком экране разрешили перестроиться (reflow), а не отдельный UI и не рескин.
- **Погружение не страдает.** Рамки, орнаменты, карточки и анимации сеттингов работают и на телефоне;
  упрощаем расположение, а не оформление.
- **Сохранение.** Ни один десктопный юзкейс не должен стать хуже. Каждая правка проверяется и на
  широком экране тоже.
- **Порог телефона — палец, а не курсор.** Всё, что завязано на hover и правую кнопку, на тач-экране
  получает явный путь.

## 1. Что уже есть (на этом строим)

Задел под адаптив частичный, но ненулевой — не начинаем с чистого листа:

- `apps/web/index.html:7` — корректный `<meta name="viewport" content="width=device-width, initial-scale=1.0">`.
- `apps/web/src/screens/sheet/dialogs/context.tsx:36-42` — `window.matchMedia('(min-width: 1440px)')`
  уже переключает подробности записи между **боковой панелью** (широкий экран) и **модалкой** (узкий).
  Это готовый паттерн рантайм-брейкпоинта — его выносим в общий хук.
- Контейнерные запросы в CSS: `apps/web/src/ui/theme/base.css:1560,1565` (`section-list`),
  `apps/web/src/ui/theme/party.css:155,409`. Значит механизм `@container` в проекте уже живёт.
- Глобально уважается `prefers-reduced-motion` (`App.tsx`, CSS).

Чего нет: ширинных брейкпоинтов на **каркасах экранов** D&D/custom — все они колонки фиксированной
ширины внутри `h-screen overflow-clip`. Первые экраны, переведённые на адаптив, — листы «Зова Ктулху»
(см. §3, «Зов Ктулху»): там же появились хук `ui/useBreakpoint.ts` и префиксы `max-sm:/max-md:/max-lg:`.

## 2. Брейкпоинты и механизм

Договорённость (поправить при желании):

| Имя      | Ширина        | Что это                         |
| -------- | ------------- | ------------------------------- |
| `phone`  | `< 640px`     | телефон, одна колонка           |
| `tablet` | `640–1023px`  | планшет, две колонки, узкие рейлы|
| `desktop`| `≥ 1024px`    | текущая вёрстка, без изменений   |
| `wide`   | `≥ 1440px`    | уже есть (боковая панель деталей)|

Три инструмента, каждый для своего:

1. **Общий хук `useBreakpoint`** — вынести из `context.tsx` (`PANE_QUERY`) в `apps/web/src/ui/useBreakpoint.ts`
   (`matchMedia` + подписка, SSR-safe-дефолт). Им управляем тем, что меняет **структуру** (рейл ↔ нижняя
   панель, боковая панель ↔ модалка, вкл/выкл колонки). `context.tsx` переводим на него же.
   **Сделано:** `ui/useBreakpoint.ts` — `useMediaQuery(query)`, `useAtLeast('tablet' | 'desktop' | 'wide')`
   и `BREAKPOINTS` (640/1024/1440). Им пользуются экраны «Зова Ктулху»; `context.tsx` (`useWideSheet`)
   ещё не переведён.
2. **Tailwind-брейкпоинты** (`sm/md/lg`) — для **раскладочных мелочей внутри одного каркаса**
   (отступы, размеры шрифта, число колонок грида). Сейчас дефолтные значения Tailwind подойдут; если
   меняем — правим `tailwind.config`/preset и фиксируем здесь. Пишем их **сверху вниз**:
   `max-lg:` / `max-md:` / `max-sm:` — так десктопные классы остаются как были, а узкие только
   добавляются (десктоп `≥ 1024px` не может поменяться). Для гридов, которые сидят в колонке неизвестной
   ширины, — `grid-cols-[repeat(auto-fit,minmax(min(16rem,100%),1fr))]` (подстраивается под свою
   ширину без `@container`).
3. **`@container`** — там, где компонент должен реагировать на **свой** размер, а не на экран (карточки
   в гриде, списки). Уже используется — продолжаем в том же стиле.

Правило выбора: меняется **что показываем / куда кладём большие блоки** → хук; меняется **как выглядит
один блок** → Tailwind/`@container`.

## 3. Разбор по экранам

Для каждого: как сейчас (с привязкой к коду) → цель на телефоне.

- **Сейчас:** `SheetScreen.tsx:41` корень `h-screen overflow-clip`; раскладка `flex h-full` =
  вертикальный рейл `shrink-0` (`ui/Rail.tsx:6`, `w-[76px]`) + колонка героя `shrink-0`
  (`HeroColumn.tsx:43`, `w-[340px]`) + секция `flex-1 px-10`. На телефоне 416px хрома съедают экран,

## 4. Меняющиеся юзкейсы (внимательно!)

Это места, где взаимодействие на телефоне становится **другим**, а не просто уже:

1. **Хотбар: карточка и подсказка.** Сейчас: ЛКМ — применить, **ПКМ — карточка** (`Hotbar.tsx:78,97`),
   подсказка только по hover/focus (`HudTip.tsx:43-49`), тап по слоту **сразу применяет** действие и
   списывает ресурс (`Hotbar.tsx:129-143`). На тач-экране нет ни правого клика, ни hover → карточку и
   подсказку открыть нечем, а палец бьёт «применить» без шанса посмотреть.
   **Решение (выбрать):** (а) первый тап — карточка/инспект, второй — применить; либо (б) long-press —
   карточка, тап — применить; кнопка «применить» внутри карточки. На десктопе поведение сохранить.
   Это самый важный пункт всей мобилизации.
2. **Навигация листа:** вертикальный рейл (hover-подписи) → нижние вкладки с подписями всегда.
3. **Боковые панели боя и стола** (лог/чат/колоды) из «всегда на экране» → «по кнопке» (шторка/вкладка).
4. **Колонка героя** из «всегда рядом» → «свёрнута, HP/рассудок/КБ всегда видны, остальное по тапу».
5. **Hover-подсказки везде** (`title`, кастомные тултипы) → дублировать тапом/long-press или выносить
   текст на экран; критичное (смысл индикатора синхронизации) не должно жить только в `title`.
6. **`overflow-clip` → вертикальный скролл** на phone (на desktop оставить «без скролла страницы»).

## 5. Что сохранить без изменений (десктоп-инварианты)

- Раскладка `≥ 1024px` (и `wide ≥ 1440px` с боковой панелью деталей) — пиксель в пиксель как сейчас.
- Десктопный хотбар: ЛКМ — применить, ПКМ — карточка, hover-подсказка.
- «Страница не скроллится, скроллятся только списки» — поведение десктопа.
- Все сеттинги, рамки, орнаменты, анимации — работают одинаково.

## 8. Риски

- **Хотбар (§4.1)** — главный риск: поменять поведение на тач, не задев десктоп. Развести по
  `useBreakpoint` / `pointer: coarse`, а не ломать общий обработчик.
- **`h-screen` на мобильных браузерах** — адресная строка меняет высоту; использовать `100dvh`/`svh`
  вместо `h-screen` там, где перейдём на скролл.
- **Абсолютные панели боя** — при reflow легко получить наложения; переводить на поток/шторки, а не
  двигать `top/left`.
- **Регресс десктопа** — любое изменение каркаса проверять на `≥ 1024px`.
