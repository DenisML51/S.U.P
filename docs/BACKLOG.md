Рабочий файл. Статусы: `[ ]` не начато, `[~]` в работе, `[x]` готово (ветка → `dev`).
Каждая значимая задача — своя ветка от `dev`, слияние `--no-ff`, коммит одной строкой `type: описание`.
Любая визуальная правка проверяется в браузере (localhost:3000, аккаунт `dev@itd.test`) на всех сеттингах.

## 0. Решения пользователя (2026-10-24)

- Гримдарк удаляется. Все гримдарк-персонажи (Хорус) становятся тёмным фэнтези.
- Три сеттинга и их источники:
  - **Тёмное фэнтези** — Bloodborne, Warhammer, Dragon Age (готика, викторианский ужас, кованое железо, воск, кровь).
  - **Научная фантастика** — Star Wars, Mass Effect, Halo (матовые панели, плотные данные, голубой акцент).
  - **Высокое фэнтези** — D&D, Властелин колец, The Elder Scrolls (пергамент, золото, звёздный атлас).
- Цель — погружение, а не рескин: у каждого сеттинга свои рамки, кнопки, списки, панели подробностей, ховеры,
  анимации, орнаменты. Текущие рамки high-fantasy — «4 из 10», остальные хуже. Без нейрослопа.
- Процесс тем: **витрина → одобрение → раскатка.** Сначала страница-витрина на каждый сеттинг, пользователь
  правит, потом применение ко всем экранам.
- Можно: шрифты Google Fonts (через `@fontsource`, офлайн), текстуры CC0 (в `apps/web/public`, с указанием в `docs/CREDITS.md`).
- Боевой режим: перестилизация по сеттингам **без смены концепции** (хотбар BG3 остаётся).
- Подробности записей (заклинание, предмет, способность): на широком экране — панель сбоку при списке
  (как инвентарь RE9 / Control, реф `refs/image.png`), на узком — модалка. Редактирование — всегда модалка.
- КБ конечности без брони = **10 + ЛВК** (как у героя). Броня задаёт и КБ героя, и КБ каждой конечности.
- Отдых: у ресурса правило восстановления (короткий / долгий / вручную); для D&D заполняется автоматически.
- Отмена: стек истории (~50 шагов за сессию) + тост «Отменить» после каждого изменения.
- Концентрация: полноценная механика с привязкой к заклинаниям/способностям; при уроне — окно спасброска
  с кнопкой броска и «выдержал/провалил».
- НЕ делать: быстрые урон/лечение, горячие клавиши.

## 1. Механика

  (при парсинге, чтобы старые листы и серверные копии тоже читались). Тест миграции.
- `apps/web`: убрать `grimdark` из `SETTING_INFO`, `tokens.css`, `primitives.css`, `ui/art/grimdark.tsx`,

### [x] 1.2 КБ героя и конечностей
Сейчас: `armorClass` хранится и правится вручную, поэтому лист (20), «Снаряжено» (19) и броня (16) расходятся;
КБ конечностей при снятии брони = 0, при создании = 10+ЛВК.
- КБ героя вычисляется (`calculateArmorClass`) + ручной модификатор (`armorClassBonus.manual` или аналог),
  а не хранится как итог. Миграция: текущий итог − вычисленное → ручной модификатор, чтобы цифры не прыгнули.
- КБ конечности = `armor.limbACs[limb]`, если броня надета и значение задано; иначе 10 + ЛВК (с учётом
  тех же бонусов «всегда»). Плюс ручной модификатор на конечность. Щит — к КБ героя (и, опционально,
  к рукам — решить по ходу, по умолчанию нет).
- UI: в «Тело → Защита» и в окне КБ показать разбор: «броня 16 + ЛВК 2 + щит 2 + стиль 1 = 21».
- Тесты в `game-logic`.

### [x] 1.3 Отдых
- Схема: у `Resource` поле `recovery: 'short' | 'long' | 'manual'` (по умолчанию `long`), опционально
  `recoveryAmount` (для «короткий отдых возвращает одно»). Кости хитов: ресурс `hitDice` (`current/max`,
  кость по классу) — для D&D из build, для своих героев можно добавить.
- Правила (`game-logic/rules/rest.ts`):
  - короткий: тратит выбранное число костей хитов (бросок + мод. ТЕЛ, или среднее), восстанавливает
    ресурсы `short` (полностью или на `recoveryAmount`);
  - долгий: хиты в максимум, временные хиты 0, ресурсы `short` и `long` в максимум, кости хитов — половина
    от максимума (мин. 1), ячейки заклинаний, сброс счётчиков действий; концентрация снимается; рассудок не трогаем.
- D&D: правила восстановления проставляет `applyBuild` (Божественный канал, Второе дыхание и т. п. — `short`
  с `recoveryAmount: 1` / long полностью; ячейки — long).
- UI: кнопка «Отдых» (вместо иконки у ресурсов) → окно с двумя вкладками; превью «что изменится»; запись в журнал.
- Правило восстановления — поле в окне ресурса.

### [x] 1.4 Отмена
- Стек снимков в сторе (не в документе): до 50 шагов, на сессию/персонажа. Снимок до каждой правки через
  `updateCharacter`, кроме правок, пришедших синхронизацией.
- Отмена применяется как обычная правка (уходит в синхронизацию). Если документ изменился с другого
  устройства после снимка — отмена через 3-way merge (`mergeCharacters(after, after, before)`), чтобы
  не затереть чужие изменения.
- Тост после изменения: текст из журнала + «Отменить». Журнал: у последних записей кнопка «Отменить до сюда».
- Тесты стора.

### [x] 1.5 Концентрация
- Схема: `concentration?: boolean` у `Spell` и `Ability` (D&D-заклинания уже несут `concentration` в контенте —
  переносить в лист при `applyBuild`); у персонажа `concentratingOn?: { kind, id, name, startedAt }`.
- Правила: использование записи с концентрацией → начинает концентрацию (если была другая — окно
  «прервать „X“?»). Урон при концентрации → окно спасброска ТЕЛ, СЛ = max(10, ⌊урон/2⌋) (макс. 30), с
  бонусом спасброска ТЕЛ героя; «Бросить» / «Выдержал» / «Провалил». Недееспособен/без сознания/0 хитов
  → снимается автоматически. Долгий отдых снимает.
- UI: метка концентрации в статус-кластере листа и у портрета в бою, кнопка «Прекратить»;
  флажок «Концентрация» в окнах заклинания и способности; значок у записи в списках.
- Тесты.

### Дизайн-бриф сеттингов

Общее: структура и разметка одни, скин — свой. Сеттинг различается материалом, формой рамок и кнопок,
выделением, ховером, типографикой, фоном и анимациями. Основной текст — Golos (читаемость).

**Высокое фэнтези — «Атлас мага».** D&D/BG3, Властелин колец, Skyrim/Oblivion. Материал: глубокий
бирюзово-чёрный лак ночного неба, старое золото, слоновая кость; пергамент для чтения. Рамки: двойная золотая
нить (внешняя + внутренняя в 4px) с тонкой филигранью в углах; у главных панелей — гребень/медальон по
центру верхней кромки (арка BG3). Заголовки — Cormorant SC, золото, правило-шкала астролябии. Кнопки:
основная — эмаль (бирюза→тёмная) в золотом ободке с заострёнными концами (BG3 «Proceed»), вторичная — тёмная
кожа в золотой нити, тем же силуэтом; ghost — золотой текст. Списки: римские номера, выбранная строка —
золотая планка слева + мягкий свет. Ховер: углы-филигрань раскрываются, золото светлеет. Фон: звёздная
карта — тонкие окружности астролябии, созвездия, виньетка. Подробности: страница фолианта (пергамент,
буквица). Анимации: плавное «проявление» (fade + лёгкий подъём), блик по золоту при выборе.

**Научная фантастика — «Тактический терминал».** Mass Effect, Halo, Star Wars. Материал: матовый графит,
волосяные линии, сигнальный синий; оранжевый — тревога. Без бликов, свечений и рамок-скобок повсюду.
Рамки: волосяная линия, заголовок панели — полоса-ярлык с кодом («SYS·04 / НАВЫКИ»), один срез угла у главных
панелей (не у всех). Крупные цифры Tektur, индексы 01/02, коды. Кнопки: основная — сплошной синий блок со
срезом правого нижнего угла, вторичная — волосяная рамка, ховер заливает. Списки: нумерованные записи,
выбранная — сплошной синий блок с тёмным текстом (как оранжевая плашка рефа). Фон: точечная сетка,
полутоновый узор в углу, измерительные шкалы по краям. Подробности: досье — шапка с кодом, ячейки-показатели,
полутон. Анимации: быстрые, линейные — «развёртка» слева направо, мигание курсора при выборе.

**Тёмное фэнтези — «Охотничий реликварий».** Bloodborne, Warhammer, Dragon Age. Материал: чёрное железо и
тёмная кожа, потемневшая латунь с гравировкой, воск печатей, кровь; состаренный пергамент для записей.
Рамки: латунная двойная гравированная рамка, готические углы (стрельчатый шип/крестоцвет), у главных
панелей — стрельчатая арка-навершие. Заголовки — антиквa XIX века (Old Standard TT / проверить варианты),
рубрикация — первая буква красным. Кнопки: основная — тёмно-кровавый лак в латунном ободке со скошенными
«щитовыми» концами, вторичная — железная пластина в латунной нити. Списки: строки, разлинованные от руки,
маркеры-кинжалы, выбранная — кровавая закладка + тёплый свет свечи. Ховер: свет свечи снизу, тьма
сгущается по краям. Фон: туман внизу, готическая виньетка, едва заметная стрельчатая трасировка.
Подробности: пергаментная карточка с сургучной печатью. Анимации: медленные, тяжёлые — проявление из тьмы.

Сделано (2026-10-30, ветка `feat/multiclass`, задачи — свои ветки): контент (требования и владения мультикласса
по PHB 2024, у охотников на крови — по документам авторов), сборка `classes[]` с чтением старых листов, особенности
по уровню своего класса, хиты и пулы костей по размеру, общая таблица ячеек и договор отдельно, СЛ/атака/подготовка
по классу (`casters`), лучший из альтернативных КБ; окно уровня с выбором класса (плитки + карусель с причинами),
откат уровня в окне опыта, класс на каждом уровне при создании, магия по классам, СЛ классов в бою. Подробности —
в ARCHITECTURE.md. На сверку: Ведьмовские рыцари (laserllama) складывают договор с колдуном по правилу Мерсера (⅓) —
своего правила у автора не нашлось.

Исходная постановка:
- Схема: `build.classes: { classId, subclassId?, level }[]` (порядок = порядок взятия, первый — стартовый класс),
  общий уровень = сумма. Миграция: один класс → массив из одного. Бонус мастерства — по общему уровню.
- Окно нового уровня: первый шаг «какой класс повысить» (свои + «новый класс»). Новый класс доступен, если у героя
  13+ в основной характеристике **и** текущих классов, и нового (таблица требований PHB 2024).
- Владения при взятии второго класса — урезанный набор из таблицы мультикласса (не стартовый набор класса):
  без спасбросков, навыки — по таблице (плут/бард/следопыт — по одному).
- Хиты: кость класса, который повышается (первый уровень второго класса — бросок/среднее, не максимум).
  Кости хитов — по ресурсу на каждый тип кости (к6, к10…), отдых тратит/возвращает каждый пул.
- Заклинания: общий уровень заклинателя = полные + ⌈половинные/2⌉ (+ ⌊трети/3⌋ для подклассов-третей) →
  общая таблица ячеек; подготовленные/известные заклинания и характеристика — по каждому классу отдельно;
  колдун — отдельно (магия договора), его ячейки и общие тратятся друг за друга.
- Не складываются: Дополнительная атака (разные классы), Защита без доспехов (выбирается одна),
  Ячейки договора не повышают общий уровень заклинателя. Способности классов — по уровню своего класса
  (`classLevel`), масштабы (`scaling.ts`) — по уровню класса, кантрипы — по общему уровню.
- UI: подпись «Воин 3 / Волшебник 2» в шапке, карточках, партии; в магии — разделы по классам.
- Тесты: каждый пункт правил выше; повышение и откат уровня; сборка после перезагрузки (`applyBuild`).

### [ ] 8.2 Зов Ктулху: автоматическая стрельба очередью
Сейчас только 1–3 выстрела из пистолета со штрафной костью (`coc/combat.ts` `firearmModifiers`, `shots`).
Оружие с «очередь» в `uses` (`coc/content/weapons.ts`: пистолеты-пулемёты, автоматы, пулемёт) получает режим
«Очередь» (7e, Keeper Rulebook, «Automatic Fire» — сверить цифры):
- Стрелок задаёт размер очереди: от 3 пуль до (навык / 10); число очередей за раунд — пока хватает патронов.
- Каждая очередь — отдельный бросок; первая без штрафа (только обычные модификаторы), каждая следующая — +1 штрафная
  кость; после двух штрафных — вместо кости растёт сложность.
- Успех: попадает половина пуль очереди (мин. 1); экстремальный успех — все пули, половина из них пронзающие
  (максимальный урон + бросок). Урон — по каждой попавшей пуле, броня цели вычитается из каждой.
- Перенос огня на другую цель — пули, ушедшие «в промежуток», списываются (по правилу книги).
- Патроны списываются за всю очередь; осечка проверяется на каждом броске.
- Движок: чистая функция `burstFire(weapon, skill, plan)` → броски, попадания, урон, патроны; действие в `actions.ts`;
  в бою — переключатель «Одиночный / Очередь» в панели оружия (вместо 1/2/3 у автоматического оружия),
  журнал по каждой очереди. Тесты на половину/все/пронзающие и рост штрафа.
